Reading the instrument

        

          
Output is what the model writes at the cursor’s step, drawn with the same random numbers every time, so differences between steps are the model’s alone. A character’s brightness is how sure the model was of it. Point at (or tap) a character to light up what the model looked at when it wrote it; pick a head under Heads to see that head alone.

          
The trace is the run. Yellow is the loss on the text it trains on; cyan, on a tenth it never trains on; magenta, the learning rate, on its own scale; blue, the loss on the second copy of the induction test. The dashed line across is chance. Under the trace, one lane per attention head on the same time base: orange where the head copies, white where it looks at the previous character. REF, dim, is a recorded run of this same code.

          
The induction moment. Every 20 steps the model reads random characters shown twice. Nothing about them can be memorised, so the only way to predict the second copy is to find where the current character appeared before and copy what came next: an induction head. When one appears, the copy loss falls off a cliff, and the moment is written on the trace.

          
Heads takes the trained model apart. Each head’s pattern on the test shows its job: a stripe one step under the diagonal is a previous-character head; a stripe half a window back is an induction head. Knocking a head out (setting its output to zero) shows what the model loses; patching a head’s output from a clean run into a corrupted one shows what that head alone carries. Shift-click heads to knock them out while the model writes.

          
Features is a sparse autoencoder trained on the model’s residual stream after the run: a dictionary of directions, most of them off at any character. Each feature is shown with the contexts where it fires hardest, and labelled by rule when one rule covers most of them. Pin a feature at a value and the model writes with it held there.

          
Live and recorded. Your run is live. The recorded run opens instantly while yours warms up, and stands in for it on devices that cannot train the full model; everything from it is marked recorded. Its weights (2.1 MB) download only if you ask to write with it.

How it works

        

          
A character-level GPT: each character is a token, embedded with its position and passed through four transformer blocks of causal multi-head self-attention and a GELU MLP, with layer norm before each, and an output head tied to the token embedding. AdamW, a warm-up and cosine decay, gradient clipping and dropout. One window in four of every batch is random characters repeated, so that copying pays within a minute; on text alone no head learned to copy in 3,000 steps.

          
There is no machine-learning library. Every operation, forward and backward, is a WGSL compute shader written for this page: a tiled matrix multiply through workgroup memory, softmax, layer norm, attention, GELU, cross-entropy and the optimiser; and for the microscope, the induction test’s scoring, per-head knockout and patching, and the sparse autoencoder’s training and analysis. A plain TypeScript copy of the same maths checks every kernel.

          
The induction test and the moment follow Olsson et al., In-context Learning and Induction Heads (2022). The sparse autoencoder follows Bricken et al., Towards Monosemanticity (2023), and Cunningham et al., Sparse Autoencoders Find Highly Interpretable Features in Language Models (2023). Activation patching as in Meng et al., Locating and Editing Factual Associations in GPT (2022).

          
Texts from Project Gutenberg (public domain): Shakespeare’s Sonnets (ebook 1041), Alice’s Adventures in Wonderland (11), Hamlet (1524), Macbeth (1533), Romeo and Juliet (1513), Othello (1531) and King Lear (1532); and Webster’s Second New International Dictionary (1934) word list from BSD Unix.
